# Readable Code Workflow

Use as a style modifier for the current coding task, not as a request to search for or refactor unrelated code. Readability is already a baseline expectation; invoking this skill makes that emphasis explicit.

1. Read the target project's conventions and the [Human Readability](../../docs/references/code-organization-reference.md#human-readability) standard. Apply [Contextual Defaults](../../docs/references/guidance-precedence-reference.md#contextual-defaults) before generic style preferences; preserve accepted in-scope corrections, semantic order, and binding contracts. Keep the current task's scope, behavior, and delivery requirements.
2. Apply explanatory names, cohesive responsibilities, readable spacing, and straightforward control flow within that scope. Extract a helper only when its meaningful name and boundary reduce the reader's effort; do not trade visible complexity for indirection.
   For meaningful ownership changes, apply [Organization Before Authoring](../../docs/workflows/hands-off-agentic-coding-workflow.md#organization-before-authoring): sketch primary file responsibilities, public API, state lifetime, and dependency direction first. Use [Feature-Level Public APIs](../../docs/references/code-organization-reference.md#feature-level-public-apis) without fragmenting cohesive helpers; compare total navigation cost after extraction. Prefer readable statements over token compression and screen new libraries under [Libraries for Generic Mechanism](../../docs/references/code-organization-reference.md#libraries-for-generic-mechanism), not star-count guarantees.
   For changed tests, follow [test dependency groups and actual subject imports](../../docs/references/code-organization-reference.md#project-root-imports-and-paths) and [structured controller query inputs](../../docs/references/code-organization-reference.md#structured-controller-query-inputs), preserving supported exports, local overrides, and proven transport behavior.
   For ineffective declarations, guards, or configuration, apply [Human Readability](../../docs/references/code-organization-reference.md#human-readability)'s intended-contract guidance: inspect context and callers, clarify repair versus removal only if genuinely ambiguous, and repair established intent rather than preserving the defect. Verify the accepted contract; established obsolete code may be removed without clarification.
   Apply [Human Readability](../../docs/references/code-organization-reference.md#human-readability) to named enable/disable operations and direct simple state construction, and [Named Helper Results](../../docs/references/code-organization-reference.md#named-helper-results) to same-name property destructuring, including one field. Preserve event adapters, useful computations, receiver binding, live reactive reads, and return identity.
   Make independent behavioral options visible at callers with named options or keyword arguments under [Human Readability](../../docs/references/code-organization-reference.md#human-readability); reassess whether the flags hide distinct operations and preserve validation behavior.
   Apply [Function Calls Before Construction](../../docs/references/code-organization-reference.md#function-calls-before-construction) to calls and fallback expressions within their original execution scope, [Diff-Friendly Configuration Layouts](../../docs/references/code-organization-reference.md#diff-friendly-configuration-layouts) to nested responses, decorator options, and non-empty assertion objects (even one property), and [Operation Calls and Completion](../../docs/references/code-organization-reference.md#operation-calls-and-completion) without losing pending observations, concurrency, or rejection ownership. Assertion data is not the small call-argument layout exception.
   Accept [linear test expectations](../../docs/references/code-organization-reference.md#linear-test-expectations), [simple inline serializer projections](../../docs/references/code-organization-reference.md#simple-serializer-projections), and [existing inline policy allowlists](../../docs/references/code-organization-reference.md#existing-policy-allowlists) without meaningless one-use aliases. In tests, keep simple actual queries and inline expected matchers together with expanded objects; this expressly overrides construction extraction, not assertion strength. Preserve meaningful computations, permission APIs, evaluation order/count, and spread precedence; these are bounded exceptions, not permission to inline arbitrary effects.
   Use [Scoped Readability Review](../../docs/references/code-organization-reference.md#scoped-readability-review) to preserve unchanged computed/declaration and destructuring order unless the task, a real dependency, or binding convention justifies a change. Explicit normalization remains valid; do not expand an import-only correction into value-object formatting.
   Inspect derived expressions under [State Names](../../docs/references/code-organization-reference.md#state-names-and-dependency-local-ordering): name the actual transformation and full domain noun, including singular callbacks; keep unchanged pass-throughs source-domain-named. Align affected bindings and consumers without same-value aliases; preserve genuine visibility/selection names and necessary collision distinctions.
   Prefer positive `is`-prefixed application state under [State Names](../../docs/references/code-organization-reference.md#state-names-and-dependency-local-ordering), explicit derived completeness checks and existing nil predicates under [Guard Clauses](../../docs/references/code-organization-reference.md#guard-clauses-and-exceptional-responses), and identity-only arguments for [navigation](../../docs/references/code-organization-reference.md#ui-navigation-handler-names). Preserve polarity, missing-value distinctions, and record arguments that genuinely need other fields.
   Group [Mutually Exclusive Alternatives](../../docs/references/code-organization-reference.md#mutually-exclusive-alternatives) in one branching structure. Pass source values for [helper-owned derivations](../../docs/references/code-organization-reference.md#private-helper-inputs), retaining explicit dependencies. With existing Luxon, use parsed values and explicit formats rather than timestamp slicing under [Guard Clauses](../../docs/references/code-organization-reference.md#guard-clauses-and-exceptional-responses), preserving date-only and zone semantics.
   Apply [Guarded Computations](../../docs/references/code-organization-reference.md#guarded-computations) to changed conditional expressions: prefer explicit branches, respect accepted branch corrections, and retain concise scalar ternaries only with a concrete clarity reason. Preserve lazy execution and do not confuse `??`/`?.` with ternaries or add syntax-only wrappers.
   In changed actual barrels, use [semantic export groups and local labels](../../docs/references/code-organization-reference.md#service-orchestration-readability), not global alphabetical ordering or invented headings for homogeneous exports. Preserve public/type contracts and keep structural barrel checking separate.
   In single-purpose function modules, follow [Library Index Barrels](../../docs/references/code-organization-reference.md#library-index-barrels): primary named function, supporting functions/runtime constants such as cached formatters, then matching default export. Preserve initialization safety, imports, and supporting types; do not move declarations across an early use.
   Choose the [class-operation lifetime](../../docs/references/code-organization-reference.md#class-operation-lifetimes) according to the state the operation needs. Preserve genuine startup and shared-lifetime contracts.
   Resolve [environment parsing and defaults](../../docs/references/code-organization-reference.md#shared-environment-defaults) in configuration, express durations in readable human units, and keep [stable shared projections](../../docs/references/code-organization-reference.md#owner-defined-constant-projections) beside their source constants. Preserve actual values, lifetime, order, mutation boundaries, and independent test expectations.
   Apply [Optional Integration Configuration](../../docs/references/code-organization-reference.md#optional-integration-configuration) when changing how integrations are selected. Trace base and enabled consumers before moving settings; preserve independent lifecycle and routing behavior.
   For requested normalization across related implementations, use [Whole-Family Normalization](../../docs/references/code-organization-reference.md#whole-family-normalization): inspect every in-scope member before selecting the clearest existing patterns, then align structure and equivalent behavior while preserving justified role differences.
   For Vue scripts, use [Setup Priority and Breadcrumbs](../../docs/references/vue-component-authoring-reference.md#setup-priority-and-breadcrumbs) to keep cosmetic state below domain workflows and existing breadcrumbs last when lifecycle/dependencies permit. Keep [watcher-local hydration](../../docs/references/vue-component-authoring-reference.md#watcher-local-hydration) beside its explicit sources and consume the observed domain value.
   Check [Model Bindings Before Props](../../docs/references/vue-component-authoring-reference.md#model-bindings-before-props) separately from SFC block order, and use [Mutable Component Workflow Snapshots](../../docs/references/vue-component-authoring-reference.md#mutable-component-workflow-snapshots) without changing private composable bookkeeping.
   For component interactions, use [Required Selections and Nullable Drafts](../../docs/references/vue-component-authoring-reference.md#required-selections-and-nullable-drafts) and [Form-Owned Submission and Public Component APIs](../../docs/references/vue-component-authoring-reference.md#form-owned-submission-and-public-component-apis) for selection and post-save completion contracts.
   For data composables and route-backed tables, use [Model-Mirror Composables](../../docs/references/vue-component-authoring-reference.md#model-mirror-composables-and-editor-ownership) and [URL-Backed Server Table Options](../../docs/references/vue-component-authoring-reference.md#url-backed-server-table-options) for their authoring contracts; keep error/presentation and fetch/loading ownership explicit.
   For Vue tables, apply the [header authoring preference](../../docs/references/vue-component-authoring-reference.md#setup-priority-and-breadcrumbs) separately from ordering-only edits, and prefer [template-local display formatting](../../docs/references/vue-component-authoring-reference.md#template-local-display-formatting) over presentation-only row copies. Inspect consumers before removing projections; preserve editing-state and item contracts.
   Put explicit Vue query-result types at the [computed boundary](../../docs/references/vue-component-authoring-reference.md#computed-result-type-boundaries) when the consumer contract permits; preserve required literal inference. For routine save failures, keep [UI-owned snackbar feedback and ordinary retry](../../docs/references/code-organization-reference.md#error-ownership-and-local-recovery), preserving edits, validation, and uncertain-write safety.
   Use multiline braced JavaScript/TypeScript [guards](../../docs/references/code-organization-reference.md#guard-clauses-and-exceptional-responses) by default. A guard with a short condition and only a bare `return` may also fit on one line. Keep a blank line before the next logical step and follow local formatting and style rules without changing conditions or errors. Default [optional collections](../../docs/references/code-organization-reference.md#optional-collections-before-transformations) before projecting; destructuring handles undefined, not null. Prefer existing Lodash `first`/`last` for endpoint reads while retaining empty-collection behavior and positional contracts.
   Separate [machine enum values and UI labels](../../docs/references/code-organization-reference.md#machine-enum-values-and-ui-labels); inspect producers, consumers and integration mapping without changing raw external contracts. Exact API snapshots retain the [response shape and owning type](../../docs/references/code-organization-reference.md#serialized-transport-type-names); deliberately transformed records are distinct contracts.
   Add reciprocal file/function [synchronization comments](../../docs/references/code-organization-reference.md#mirrored-contract-comments) for intentional mirrors, keeping test-only encoders private. Reuse [entrypoint-owned Ruby bootstrapping](../../docs/references/code-organization-reference.md#entrypoint-owned-ruby-root-bootstrap) once with root-joined internals and unrelated-cwd/combined-loader proof.
   Prefer [effect-oriented private method slices](../../docs/references/code-organization-reference.md#effect-oriented-method-slices) before more services, preserving transaction, lock, cancellation, order, lazy execution and errors; leave small clear methods intact. Use [explicit fixed-family errors](../../docs/references/code-organization-reference.md#explicit-fixed-family-error-types) with unchanged codes/messages/statuses and catch contracts rather than code-selected indirection.
   For effects with distinct failure boundaries, apply the same guidance to attach diagnostic labels to the operations, not to separate progress bookkeeping.
   Preserve [reactive presentation defaults](../../docs/references/vue-component-authoring-reference.md#reactive-presentation-defaults) and [query bindings with caller-owned export selection](../../docs/references/vue-component-authoring-reference.md#query-bindings-and-caller-owned-export-selection): keep composable-owned metadata/state reactive and bulk selection with its caller rather than introducing snapshot aliases or ownership shifts.
3. Follow the current request's [Work Level](../autopilot/workflow.md#work-levels) for verification and [review](../code-review/workflow.md). Keep ownership, effects, and failure paths clear while editing; readability is not a quality downgrade in quick tweak mode, which stops after the mechanical edit without agent-initiated post-edit verification or re-review. This modifier does not authorize a separate release, new dependencies, unrelated formatting, or repository-wide cleanup.

For a standalone request to find and improve hard-to-read code, use [Simplify](../simplify/workflow.md) instead.
