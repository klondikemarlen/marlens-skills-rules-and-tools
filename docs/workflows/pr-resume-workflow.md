# Resume a Pull Request Conversation

Use this workflow when the user wants their next prompt in the conversation that worked on a particular GitHub pull request, not when they want a message forwarded to another agent.

1. Start with the full PR URL and the current ompi profile. If the installed [omp-instance-control](https://github.com/klondikemarlen/omp-instance-control) provides a documented in-terminal PR continuation command, use its user-invoked interface. Let it resolve the URL and check the current and target sessions; do not guess its syntax from an issue or substitute a shell-launched OMP process.
2. For lookup only, ompi 2.0.1 supports `ompi control work find --json URL`. Pass the qualified URL as one argument. A work claim is the conversation's assertion, not proof that it created the PR, permission to take over the session, or evidence that the transcript is still available. No claim does not rule out older, unregistered work. Do not search unrelated profiles or expose private transcripts to find a match.
3. Prefer evidence tied to the PR's actual creation or published changes over a title, working directory, or incidental URL mention. When several candidates remain, show only distinguishing local-safe evidence (such as branch, work summary, or last activity) and let the user select or cancel. Do not choose the newest by default.
4. Identify whether the proposed operation resumes the original or forks its history. Preserve the current saved conversation. Do not interrupt a live owner, take a lease, change profiles, or silently substitute a fork. If a switch is unavailable or unsafe, keep the current session intact. Offer the existing owner terminal for live work, or the native session picker for a known saved conversation; label these as manual alternatives, not a completed handoff.

Report a switch only after the runtime confirms the selected conversation is active in the same terminal. For acceptance QA use two disposable saved conversations: check the next prompt has the selected history, the starting conversation remains resumable, and cancel/no-match leaves it active. A lookup result, submitted peer message, or printed resume command proves none of these outcomes.
