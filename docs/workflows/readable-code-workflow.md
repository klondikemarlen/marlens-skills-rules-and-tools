# Readable Code Workflow

Use as a style modifier for the current coding task, not as a request to search for or refactor unrelated code. Readability is already a baseline expectation; invoking this skill makes that emphasis explicit.

1. Read the target project's conventions and the [Human Readability](../references/code-organization-reference.md#human-readability) standard. Apply [Contextual Defaults](../references/guidance-precedence-reference.md#contextual-defaults) before generic style preferences; preserve accepted in-scope corrections, semantic order, and binding contracts. Keep the current task's scope, behavior, and delivery requirements.
2. Apply explanatory names, cohesive responsibilities, readable spacing, and straightforward control flow within that scope. Extract a helper only when its meaningful name and boundary reduce the reader's effort; do not trade visible complexity for indirection.
   For ineffective declarations, guards, or configuration, apply [Human Readability](../references/code-organization-reference.md#human-readability)'s intended-contract guidance: inspect context and callers, clarify repair versus removal only if genuinely ambiguous, and repair established intent rather than preserving the defect. Verify the accepted contract; established obsolete code may be removed without clarification.
   Apply [Human Readability](../references/code-organization-reference.md#human-readability) to named enable/disable operations and direct simple state construction, and [Named Helper Results](../references/code-organization-reference.md#named-helper-results) to same-name property destructuring, including one field. Preserve event adapters, useful computations, receiver binding, live reactive reads, and return identity.
   Make independent behavioral options visible at callers with named options or keyword arguments under [Human Readability](../references/code-organization-reference.md#human-readability); reassess whether the flags hide distinct operations and preserve validation behavior.
   Apply [Function Calls Before Construction](../references/code-organization-reference.md#function-calls-before-construction) to calls and fallback expressions within their original execution scope, [Diff-Friendly Configuration Layouts](../references/code-organization-reference.md#diff-friendly-configuration-layouts) to nested responses, decorator options, and non-empty assertion objects (even one property), and [Operation Calls and Completion](../references/code-organization-reference.md#operation-calls-and-completion) without losing pending observations, concurrency, or rejection ownership. Assertion data is not the small call-argument layout exception.
   Accept [simple inline serializer projections](../references/code-organization-reference.md#simple-serializer-projections) and [existing inline policy allowlists](../references/code-organization-reference.md#existing-policy-allowlists) without meaningless one-use aliases. Preserve meaningful computations, permission APIs, evaluation order/count, and spread precedence; these are bounded exceptions, not permission to inline arbitrary effects.
   Use [Scoped Readability Review](../references/code-organization-reference.md#scoped-readability-review) to preserve unchanged computed/declaration and destructuring order unless the task, a real dependency, or binding convention justifies a change. Explicit normalization remains valid; do not expand an import-only correction into value-object formatting.
   Inspect derived expressions under [State Names](../references/code-organization-reference.md#state-names-and-dependency-local-ordering): name the actual transformation and full domain noun, including singular callbacks; keep unchanged pass-throughs source-domain-named. Align affected bindings and consumers without same-value aliases; preserve genuine visibility/selection names and necessary collision distinctions.
   Prefer positive `is`-prefixed application state under [State Names](../references/code-organization-reference.md#state-names-and-dependency-local-ordering), explicit derived completeness checks and existing nil predicates under [Guard Clauses](../references/code-organization-reference.md#guard-clauses-and-exceptional-responses), and identity-only arguments for [navigation](../references/code-organization-reference.md#ui-navigation-handler-names). Preserve polarity, missing-value distinctions, and record arguments that genuinely need other fields.
   Group [Mutually Exclusive Alternatives](../references/code-organization-reference.md#mutually-exclusive-alternatives) in one branching structure. Pass source values for [helper-owned derivations](../references/code-organization-reference.md#private-helper-inputs), retaining explicit dependencies. With existing Luxon, use parsed values and explicit formats rather than timestamp slicing under [Guard Clauses](../references/code-organization-reference.md#guard-clauses-and-exceptional-responses), preserving date-only and zone semantics.
   Apply [Guarded Computations](../references/code-organization-reference.md#guarded-computations) to changed conditional expressions: prefer explicit branches, respect accepted branch corrections, and retain concise scalar ternaries only with a concrete clarity reason. Preserve lazy execution and do not confuse `??`/`?.` with ternaries or add syntax-only wrappers.
   In changed actual barrels, use [semantic export groups and local labels](../references/code-organization-reference.md#service-orchestration-readability), not global alphabetical ordering or invented headings for homogeneous exports. Preserve public/type contracts and keep structural barrel checking separate.
   For requested normalization across related implementations, use [Whole-Family Normalization](../references/code-organization-reference.md#whole-family-normalization): inspect every in-scope member before selecting the clearest existing patterns, then align structure and equivalent behavior while preserving justified role differences.
   For Vue scripts, use [Setup Priority and Breadcrumbs](../references/vue-component-authoring-reference.md#setup-priority-and-breadcrumbs) to keep cosmetic state below domain workflows and existing breadcrumbs last when lifecycle/dependencies permit. Keep [watcher-local hydration](../references/vue-component-authoring-reference.md#watcher-local-hydration) beside its explicit sources and consume the observed domain value.
   Check [Model Bindings Before Props](../references/vue-component-authoring-reference.md#model-bindings-before-props) separately from SFC block order, and use [Mutable Component Workflow Snapshots](../references/vue-component-authoring-reference.md#mutable-component-workflow-snapshots) without changing private composable bookkeeping.
   For data composables and route-backed tables, use [Model-Mirror Composables](../references/vue-component-authoring-reference.md#model-mirror-composables-and-editor-ownership) and [URL-Backed Server Table Options](../references/vue-component-authoring-reference.md#url-backed-server-table-options) for their authoring contracts; keep error/presentation and fetch/loading ownership explicit.
   For Vue tables, apply the [header authoring preference](../references/vue-component-authoring-reference.md#setup-priority-and-breadcrumbs) separately from ordering-only edits, and prefer [template-local display formatting](../references/vue-component-authoring-reference.md#template-local-display-formatting) over presentation-only row copies. Inspect consumers before removing projections; preserve editing-state and item contracts.
   Put explicit Vue query-result types at the [computed boundary](../references/vue-component-authoring-reference.md#computed-result-type-boundaries) when the consumer contract permits; preserve required literal inference. For routine save failures, keep [UI-owned snackbar feedback and ordinary retry](../references/code-organization-reference.md#error-ownership-and-local-recovery), preserving edits, validation, and uncertain-write safety.
3. Follow the current request's [Work Level](hands-off-agentic-coding-workflow.md#work-levels) for verification and [review](code-review-workflow.md). Keep ownership, effects, and failure paths clear while editing; readability is not a quality downgrade in quick tweak mode, which stops after the mechanical edit without agent-initiated post-edit verification or re-review. This modifier does not authorize a separate release, new dependencies, unrelated formatting, or repository-wide cleanup.

For a standalone request to find and improve hard-to-read code, use [Simplify](simplify-workflow.md) instead.
