# Readable Code Workflow

Use as a style modifier for the current coding task, not as a request to search for or refactor unrelated code. Readability is already a baseline expectation; invoking this skill makes that emphasis explicit.

1. Read the target project's conventions and the [Human Readability](../references/code-organization-reference.md#human-readability) standard. Apply [Contextual Defaults](../references/guidance-precedence-reference.md#contextual-defaults) before generic style preferences; preserve accepted in-scope corrections, semantic order, and binding contracts. Keep the current task's scope, behavior, and delivery requirements.
2. Apply explanatory names, cohesive responsibilities, readable spacing, and straightforward control flow within that scope. Extract a helper only when its meaningful name and boundary reduce the reader's effort; do not trade visible complexity for indirection.
   Apply [Human Readability](../references/code-organization-reference.md#human-readability) to named enable/disable operations and direct simple state construction, and [Named Helper Results](../references/code-organization-reference.md#named-helper-results) to same-name property destructuring, including one field. Preserve event adapters, useful computations, receiver binding, live reactive reads, and return identity.
   Keep unchanged computed projections source-domain-named through their return and consumers under [State Names](../references/code-organization-reference.md#state-names-and-dependency-local-ordering); retain meaningful transformation/role names and necessary collision avoidance.
   Prefer positive `is`-prefixed application state under [State Names](../references/code-organization-reference.md#state-names-and-dependency-local-ordering), explicit derived completeness checks and existing nil predicates under [Guard Clauses](../references/code-organization-reference.md#guard-clauses-and-exceptional-responses), and identity-only arguments for [navigation](../references/code-organization-reference.md#ui-navigation-handler-names). Preserve polarity, missing-value distinctions, and record arguments that genuinely need other fields.
   Group [Mutually Exclusive Alternatives](../references/code-organization-reference.md#mutually-exclusive-alternatives) in one branching structure. Pass source values for [helper-owned derivations](../references/code-organization-reference.md#private-helper-inputs), retaining explicit dependencies. With existing Luxon, use parsed values and explicit formats rather than timestamp slicing under [Guard Clauses](../references/code-organization-reference.md#guard-clauses-and-exceptional-responses), preserving date-only and zone semantics.
   For requested normalization across related implementations, use [Whole-Family Normalization](../references/code-organization-reference.md#whole-family-normalization): inspect every in-scope member before selecting the clearest existing patterns, then align structure and equivalent behavior while preserving justified role differences.
   For Vue scripts, use [Setup Priority and Breadcrumbs](../references/vue-component-authoring-reference.md#setup-priority-and-breadcrumbs) to keep cosmetic state below domain workflows and existing breadcrumbs last when lifecycle/dependencies permit. Keep [watcher-local hydration](../references/vue-component-authoring-reference.md#watcher-local-hydration) beside its explicit sources and consume the observed domain value.
   Check [Model Bindings Before Props](../references/vue-component-authoring-reference.md#model-bindings-before-props) separately from SFC block order, and use [Mutable Component Workflow Snapshots](../references/vue-component-authoring-reference.md#mutable-component-workflow-snapshots) without changing private composable bookkeeping.
3. Follow the current request's [Work Level](hands-off-agentic-coding-workflow.md#work-levels) for verification and [review](code-review-workflow.md). Keep ownership, effects, and failure paths clear while editing; readability is not a quality downgrade in quick tweak mode, which stops after the mechanical edit without agent-initiated post-edit verification or re-review. This modifier does not authorize a separate release, new dependencies, unrelated formatting, or repository-wide cleanup.

For a standalone request to find and improve hard-to-read code, use [Simplify](simplify-workflow.md) instead.
